# Backend & Database (Supabase)

Этот каталог содержит структуру базы данных, миграции, RLS политики и Edge Function для бухгалтерского агентства «Учётка».

## 1. Схема базы данных
- `tax_types` — справочник налоговых режимов («Единый налог», «Общий режим» и др.) с автоматическим описанием ставок `rate_description`.
- `users` — профили сотрудников агентства с ролями `'accountant'` (бухгалтер) и `'manager'` (руководитель).
- `companies` — карточки обслуживаемых компаний и ИП (клиентов агентства). Бухгалтер привязан через `owner_id`; также можно задать район налоговой и куратора.
- `tasks` — задачи по сдаче отчетности и документов (`doc_type`, `due_date`, `status`, `wait_until`), исполнители и контролирующие хранятся в `task_assignees`.
- `task_recurrence_series` — месячные, квартальные и годовые повторы задач.
- `notifications` — журнал уведомлений для каждого бухгалтера о дедлайнах и изменениях.

## 2. Развертывание в Supabase
1. Создайте проект на [supabase.com](https://supabase.com).
2. Перейдите в **SQL Editor** и выполните скрипт из файла:
   `supabase/migrations/20260927000000_init_accounting_schema.sql`
3. Если ранее применяли миграцию `20260928000000_manager_invite_codes.sql`, выполните
   `supabase/migrations/20261010000000_restore_role_access.sql`, чтобы убрать проверку
   кода приглашения и восстановить исходные политики доступа.
4. Для вкладки документов и приватной загрузки сканов выполните:
   `supabase/migrations/20261012000000_company_documents.sql`
   Она создаёт таблицу метаданных и закрытый Storage bucket `company-documents`.
5. Для включения ежедневных напоминаний выполните:
   `supabase/migrations/20260927000001_setup_reminders_cron.sql`
6. Для группировки клиентов, нескольких исполнителей/контролирующих и повторяющихся задач выполните:
   `supabase/migrations/20261023000000_task_assignment_recurrence.sql`
   Перед запуском убедитесь, что расширение `pg_cron` доступно в **Database -> Extensions**.
   Миграция создаёт RPC для отдельных задач на каждую выбранную компанию и ежедневное
   задание, которое создаёт следующие задачи серии в пределах 30 дней до срока. Назначения
   старых задач миграция переносит с владельца компании. Для задач без повтора расписание
   не создаётся.
7. В **Project Settings -> API** скопируйте:
   - `Project URL` -> в `.env` как `VITE_SUPABASE_URL`
   - публичный ключ `anon`/`publishable` -> в `.env` как `VITE_SUPABASE_ANON_KEY`
   - никогда не используйте `service_role` или `sb_secret_` ключи в браузере или переменных `VITE_*`

### Тестовая регистрация без подтверждения email

Для тестового проекта отключите подтверждение в панели Supabase:

1. Откройте **Authentication -> Providers -> Email**.
2. Отключите **Confirm email** и сохраните изменения.
3. Повторите регистрацию в приложении.

Это настройка проекта Supabase, и её нельзя безопасно отключить из клиентского кода.
При включённом подтверждении регистрация не создаёт активную сессию; приложение покажет
инструкцию вместо перехода в неавторизованное состояние. Не добавляйте `service_role`
или `sb_secret_` ключ в браузер ради обхода этой настройки.

### Демо-данные панели руководителя

Чтобы показать панель аккаунта `aigul1111@gmail.com` с компаниями и задачами трёх сотрудников:

1. Убедитесь, что аккаунт Айгуль уже зарегистрирован в Supabase Auth.
2. Выполните `supabase/seed_aigul_manager_demo.sql` в SQL Editor после миграций.
3. Скрипт создаст три подтверждённых демо-аккаунта с паролем `Demo-2026-Staff!`,
   по две демонстрационные компании и по девять задач на каждого. Используйте эти
   аккаунты только для тестирования; адреса `@example.com` зарезервированы для примеров.

## 3. Edge Function (Напоминания на Email)
Функция расположена в `supabase/functions/send-reminders/index.ts`.
Для деплоя через Supabase CLI:
```bash
supabase functions deploy send-reminders --no-verify-jwt
supabase secrets set RESEND_API_KEY=re_your_api_key
```

## 4. Realtime
В миграции автоматически включена публикация `supabase_realtime` для таблиц `tasks`, `companies`, `notifications`. Это обеспечивает мгновенное обновление панели руководителя (`/manager`) при любых изменениях задач бухгалтерами без перезагрузки страницы.
